# Android focus and connectivity

The project-owned `PacificMobile` Godot v2 plugin exposes only audio-focus state and the default network handle/kind. It reads no microphone, telephone number, contacts, location, SSID or carrier identity. The APK retains only its existing internet, network-state and vibration permissions. Java callbacks publish small values; Godot reads them on its own thread. Native calls fail closed without logging exception contents.

Foreground audio requests use game/music attributes, a single retained focus request and the OS main-thread listener. Duckable/transient loss pauses local driving and audio rather than leaving an unattended car accelerating. Offline state checkpoints through the ordinary lifecycle path; online sends Away and suspends transport processing. Music pauses at its current position; interrupted one-shot cues are discarded. A background window abandons focus. Audio gain restores selected sound levels while leaving driving paused. Explicit Resume retains the offline three-second countdown or the online fresh-touch rule. Permanent loss/denial exposes Retry Audio, which keyboard, gamepad and touch can reach. Audio gain cannot foreground a background window. These choices follow the [Android audio-focus contract](https://developer.android.com/media/optimize/audio-focus).

The default network is polled only while the window is active. A changed handle reconnects an established client using its existing token and deadline. It does not create a new identity, reset the reservation timer or locally resurrect a race. The OS route query uses [ConnectivityManager](https://developer.android.com/reference/android/net/ConnectivityManager#getActiveNetwork()). A first online start on a reported cellular route shows Continue/Cancel before the directory or ENet operation. Cancel starts nothing. Continue records the optional schema-1 profile flag; old profiles remain valid. If preference saving fails, consent remains valid for the current process and a normal save notice is queued. Wi-Fi/unknown routes are not labeled cellular. Physical VPN/carrier cases remain device tests.

Confirmation dialogs dismiss/release text input first. Mobile Direct Connect does not open the IME automatically. Mobile confirmations use game styling, borderless presentation and at least 48-point Continue/Cancel buttons, set through the dialog's theme minima so engine layout retains them. Android Back cancels the active modal before navigating the page behind it. Replacing a modal hides its predecessor before deferred deletion, preserving the engine's exclusive-child contract.

`tools/android_services.py` compiles the original Java source against the checksum-pinned Godot 4.6.3 Android library and API 36 with JDK 17. A deterministic AAR contains only this bridge and its registration manifest. The standard [Godot v2 export plugin](https://docs.godotengine.org/en/4.6/tutorials/platform/android/android_plugin.html) adds it to APK/AAB exports. Build provenance records source/compiler/library/AAR hashes. The exporter verifies registration metadata and the bridge DEX class before success; this structural gate is separate from actually running Android. Desktop packages exclude the editor plugin/Android sources and keep their existing native adapters.

`--mobile-services-probe` is an explicit read-only installed-APK diagnostic: it checks the singleton, granted audio focus and bounded route values, then abandons focus and exits. Source tests cover interruption, touch release, checkpoint identity, frozen Resume, music/cue behavior, explicit retry, window ownership, cellular Cancel/Continue, failed-save session consent and cold persistence. Real ENet tests cover default-route transport replacement with unchanged identity/race/deadline. Android emulator evidence separately records actual telephony focus loss, native checkpoint recovery, cellular route/consent and handover. Emulator evidence is not a real telephone call, physical carrier transition, hardware listening or thermal acceptance.
