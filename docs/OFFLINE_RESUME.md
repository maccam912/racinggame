# Mobile offline recovery

`suspended_race.json` uses the existing schema-1 atomic envelope and native profile lease. Its payload has format 1 and the complete gameplay content hash. A mobile focus/pause transition freezes the offline world, cancels driving input, then saves all controller states, ordered progress, exact timer and phase, seed/roster, bot planning/input state and School objective state. Repeated focus/pause notifications do not rewrite the checkpoint. Online races are excluded.

Controller doubles are encoded as eight little-endian bytes and Vector3 values as three native float32 values, written in lowercase hexadecimal. This preserves the exact local simulation values without using the quantized network snapshot or object deserialization. The decoder whitelists current script fields, types, finite values, bounds, roster, input and route-query contracts before a new race scene consumes the data. Presentation events are transient and cleared. Loading enforces the component envelope size limit.

A surviving process offers its ordinary Pause menu; Resume freezes simulation through the three-second safety countdown. Interrupted Time Trials become invalid for records. A cold process first offers Resume Offline Race or Discard, ahead of onboarding. Resume uses staged track loading and preserves the race UUID; Cup also requires the same active Cup/event. A cold interrupted Trial instead starts a fresh standing-start run with a new UUID and no old ghost samples. Back exits while preserving the saved race.

Unknown newer payload formats, mismatched content and future envelopes remain preserved until explicit Discard. Resume is unavailable for unsupported data. Explicit new-race/menu transitions and committed results clear known checkpoints. The checkpoint remains after resume until the next save, explicit departure or successful commit, allowing recovery if a later OS termination has no final callback. Save failures remain visible on Pause. Result UUID journals prevent a recovered result from committing twice; recovery itself writes no race stats. School completion retains its checkpoint if the profile write fails and offers Retry Save.

`race_archive_tests.gd` compares eight cars and bot planning through 120 continuation ticks after a cold JSON round trip, tests exact lap timing, malformed data, future/content preservation, Cup identity/single commit, School state and Trial/online exclusions. `checkpoint_ui_tests.gd` exercises actual staged-loader/menu actions, touch cancellation, duplicate notifications, countdown freeze, Trial restart and explicit Discard. Native rendered references cover 100/150% and unsupported data. Android emulator evidence separately records real Home, force-stop and cold touch Resume. None establishes physical power-loss, phone-call, device thermal or human usability acceptance.
